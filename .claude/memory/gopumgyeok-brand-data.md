**이미지 출처**: `0007/assets/`의 44장은 전부 이 카탈로그 PDF 크롭본이다. 추출 방식 = `pymupdf`로 300%(3x) 렌더링 → PIL 좌표 크롭 → JPG 82% 최적화. 재추출이 필요하면 동일 방식을 쓰되, 원본 PDF는 이전 claude.ai 컨테이너 경로(`/mnt/user-data/uploads/`)에 있었으므로 **로컬에는 없다 — 사용자에게 다시 받아야 함**.

**예외 — 02 메뉴 고기 9종은 더 이상 카탈로그 크롭이 아니다(2026-09-03).** `meat_*.jpg`(카탈로그 크롭,
25~35KB)는 여전히 파일로 남아있지만 `data/content.json`은 전부 `meat_*.png`(나무 테이블 배경 +
와사비 접시 + 반짝이 아이콘 스타일의 AI 생성 이미지, 개당 2.2~2.4MB)를 가리킨다 — 사용자가
명시적으로 png 전환을 요청했고, 용량이 원본 대비 약 90배라는 점을 알린 뒤에도 그대로 진행을
선택했다([[gopumgyeok-font-size-rule-exception]]과 같은 패턴 — 트레이드오프를 알리고 사용자
선택을 존중). `meat_dwaeji.png`(돼지 한판)만 처음엔 없었는데 사용자가 세션 도중 직접
파일시스템에 추가했다. 9종 총합 약 20MB로, 최적화(리사이즈/압축) 없이 그대로 배포 중 —
[[gopumgyeok-open-issues]] 참고.

**같은 패턴이 2026-09-27 셀프바에서도 반복됐다.** 셀프바는 원래 `sb_*.jpg`(180×180, 개당
5~10KB, 흰 배경이 이미지에 이미 구워진 카탈로그풍 크롭) 8종만 `content.json`에 연결돼 있었다
(CLAUDE.md "알려진 이슈 2"가 이 8종만 노출을 "의도된 여분"이라고 설명하는데, 이건 이 날짜
이후로는 사실이 아니다 — 사용자가 참고 이미지를 주며 25종 전체를 보여달라고 요청해 24종
(카탈로그상 "25종 이상"의 실물 목록, `[[gopumgyeok-brand-data]]` 상단의 셀프바 25종+ 목록과
1:1 대응)으로 확장했다). 처음엔 남아있던 `sb_*.jpg` 20종을 마저 연결했는데, 그 직후 세션
도중 `sb_*.jpg` 24개 전부가 디스크에서 사라지고 같은 이름의 `sb_*.png`(1024×1024, 투명 배경,
개당 약 1~1.4MB, meat_*.png와 같은 스타일의 AI 생성 이미지로 추정)만 남아 있는 게
`git status`로 확인됐다 — **이 세션에서 실행한 명령이 아니다**, 동시에 다른 세션/프로세스가
같은 저장소를 건드린 것으로 보인다. 결과적으로 사용자가 "jpg 경로를 png 경로로 수정해달라"
요청해 24종 전부 png로 전환했다. jpg 원본은 git 히스토리(이 커밋 이전 리비전)에서만 복구
가능하고 작업 디렉토리에는 더 이상 없다. 셀프바 24종 총합 약 24~30MB로 메뉴 9종(20MB)에
더해 미최적화 이미지 총량이 더 늘었다 — [[gopumgyeok-open-issues]] 참고.

**투명 PNG로 바꿀 때 컨테이너 배경을 꼭 같이 확인할 것.** `sb_*.jpg`는 흰 배경이 이미지 안에
구워져 있어 `.sb-item .circle`에 별도 `background`가 없어도 문제없었지만, `sb_*.png`(투명
배경)로 바꾸자 원 안으로 어두운 섹션 배경이 비쳤다. `.meat-card__circle`은 애초에
`background: var(--bg-card)`(흰색 토큰)를 갖고 있어 이 문제가 없었다 — 앞으로 어떤 원형/카드
이미지든 jpg(불투명)에서 png(투명 배경 AI컷아웃)로 바꿀 때는 컨테이너에 `--bg-card` 배경이
있는지부터 확인.
